## 一、项目定位

`yujing` 是一款**全平台中文舆情监控与 AI 研判系统**。从 10 个核心权重平台实时采集热榜与正文，通过语义聚类把碎片信号收敛为事件，再交由 LLM/Agent 做深度研判与对比分析，建立"海量噪声 → 决策结论"的处理链条。

### 核心能力体系

| 层 | 能力 | 关键特性 |
|:---|:---|:---|
| **信号层** Article | 10 平台热榜 24/7 同步 | APScheduler 120s 周期；Cookie 凭据失败透明诊断 |
| **事件层** Event | 语义聚类成事件单元 | BGE 向量 + FAISS IVF-Flat + 双层 Otsu 自适应阈值 |
| **研判层** AI Analysis | DeepSeek SSE 流式深度分析 | 词云/8 类情感/舆情倾向/ABSA 方面级/雷达 |
| **智能体层** Tool-Calling Agent | 10 原子工具自主规划 | 平均 3.5 步 / 26s；100% 完成率（20 query 评测） |
| **早报系统** Morning Brief | 定时生成日度舆情早报 | SSE 实时进度；支持调试间隔触发 |
| **异动推送** Alert | 高热事件三级推送 | critical / warning / info 自动弹窗 |
| **个性化订阅** Subscription | 关键词/事件/源订阅 + 屏蔽 | 4 维加权打分（订阅词/源/画像源/画像兴趣）+ fallback |
| **用户画像** Profile | 浏览行为画像 | 常看源 TOP / 兴趣标签 TOP，反哺推荐打分 |
| **B 站评论&弹幕** | 视频文章接入双 BERT 情绪 | 评论卡 + 弹幕卡，按情绪占比可视化 |
| **PDF 导出** | 文章/事件/早报/对话 | fpdf2 + 中文字体 / html2canvas 对比看板 |
| **两级情感** | 关键词规则（毫秒级响应）+ BERT 后台精标 | 永远不卡 CPU，首屏即有分布图 |

## 三、数据层

### 3.1 数据采集

`app/crawler/` 通过 APScheduler 以 **120 秒**周期触发全量爬取，已稳定接入 **10 个**信源：

| 类别 | 平台 | source_id | 认证 |
|:---|:---|:---|:---|
| 综合门户 | 微博热搜 | `weibo_hot_search` | Cookie |
| 综合门户 | 百度热搜 | `baidu_hot` | Cookie |
| 综合门户 | 今日头条 | `toutiao_hot` | Cookie |
| 综合门户 | 知乎热榜 | `zhihu_hot_question` | Cookie |
| 视频态势 | 哔哩哔哩 | `bilibili_hot_video` | Cookie |
| 财经专业 | 财联社电报 | `cls_hot` | 公开 |
| 财经专业 | 华尔街见闻 | `wallstreetcn_hot` | 公开 |
| 综合资讯 | 澎湃新闻 | `thepaper_hot` | 公开 |
| 科技/创投 | 36 氪 | `36kr_quick` | 公开 |
| 长尾兴趣 | 少数派 / 虎扑（按需） | `sspai_hot` / `hupu_bxj` | 公开 |

**正文抽取**：通过 Jina Reader 把目标页面转 Markdown，针对头条/B 站/知乎有专用解析（`reader.py`）。所有爬虫共享 `httpx.AsyncClient` 连接池，DB 写操作通过线程池隔离。

### 3.2 数据库设计

存储层：SQLite + SQLAlchemy，开启 **WAL 模式**确保读写并发不阻塞。核心数据模型（`app/database.py`）：

```
Article（原始情报）
  ├─ id, source_id, item_id（唯一标识）, rank, hot_value
  ├─ title, url, pub_date, fetch_time, content（Jina Markdown 正文）
  ├─ ai_summary, ai_sentiment（AI 增强字段）
  └─ extra_info（JSON 扩展：阅读量/点赞等）

Event（聚合事件）
  ├─ id, title, summary, keywords（JSON）
  ├─ article_count, platform_count, heat_score
  ├─ sentiment, latest_article_time
  └─ representative_article_id, primary_source_id

EventArticle（关联表）── event_id, article_id, relation_score, importance_score, is_primary

Topic（宏观主题）── id, title, summary, keywords, event_count, …

ArticleEmbedding（语义向量）── article_id, model_name, dim, vector(float32 bytes), updated_at

Subscription（订阅）── id, user_id, kind∈{keyword,event,source}, value, weight
Blocklist     （屏蔽）── id, user_id, term
UserProfile   （画像）── user_id, view_history, source_weights, tag_weights
```

**关系**：`Topic` ←(多)— `Event` ←(多)— `Article`，三级粒度对应宏观议题、具体事件、原始情报。

## 四、服务层

### 4.1 事件聚合（`app/services/events.py` + `semantic_index.py`）

**主路径**：BGE 向量 + FAISS IVF-Flat + Union-Find + **双层 Otsu 自适应阈值** + canonical 硬合并边。  
**Fallback**：jieba IDF 加权 Jaccard（`SEMANTIC_CLUSTER=0` 或语义路径异常时启用）。

> 完整算法详见 → [聚类算法文档](./聚类算法文档.md)。本节略。

**热度评分**：单篇文章 + 事件级 `heat_score` 公式详见 [核心原理文档](./核心原理文档.md) §1-2。

### 4.2 情感分析（`app/services/emotion.py` + `absa.py`）

| 引擎 | 模型 | 粒度 | 用途 |
|:---|:---|:---|:---|
| EmotionEngine | `Johnson8187/Chinese-Emotion`（BERT 8 类） | 整篇 → 1 个 | 情感分布柱、雷达 |
| 规则引擎（fallback） | 关键词字典 | 整篇 → 1 个 | 模型未就绪时的响应级兜底 |
| **ABSA**（独立） | DeepSeek LLM | 整篇 → N 个三元组 | 舆情倾向方面级卡 |

**请求链路保护**：BERT 后台守护线程加载，不阻塞 API 启动；事件情绪 `max_workers=1` executor + in-flight set 去重，永不打满 CPU。

> 详见 → [情感分析文档](./情感分析文档.md) + [ABSA 算法文档](./ABSA算法文档.md)。

### 4.3 主题归并（`app/services/topics.py`）

对事件层再做一次 BGE 向量 + cosine 相似度（阈值 0.70），将同一议题下多个事件归并为 `Topic`，粒度更粗。

### 4.4 全文检索（`app/services/search_engine.py`）

封装 MeiliSearch（端口 7700，随后端进程自启）：模糊中文全文 + 12 分制重排（标题全词 +12 / 关键词 +8 / 正文 +5）+ 统一搜索接口（一次返回 Event/Topic/Article 三类）。

### 4.5 个性化订阅与推荐（新增）

`/api/recommendations` 候选 200 → 4 维加权打分 → 排序：

```
score = w_keyword·订阅词命中 + w_source·订阅源命中
      + w_profile_source·画像常看源 + w_profile_tag·画像兴趣词命中
```

权重持久化到本地存储；`fallback=true` 时无命中事件按热度兜底返回 TOP。屏蔽词在 score 计算前直接剔除候选。

### 4.6 早报系统

`POST /api/ai/morning_brief/trigger` 工业级触发（立即返回 `ready/running/started`，后台异步生成）+ `GET /content` 内容直取 + `GET /pdf` 导出。前端 `AIConsultant.vue` 启动时主动触发一次 + 每 3s 轮询状态。

### 4.7 异动推送（`/api/ai/alerts`）

后台扫描时间窗内 `article_count ≥ ALERT_THRESHOLD` 的高热事件，按 `1×/2×/3×` 阈值划分 `info/warning/critical` 三级；前端独立小红点 + Brief 弹窗。

## 五、算法层

### 5.1 Tool-Calling Agent（`app/services/agent/`）

轻量自研 Agent 引擎，约 270 行核心代码，仅依赖 `langchain-core + langchain-openai`，**不引入 LangGraph / AutoGen**。

| 文件 | 职责 |
|:---|:---|
| `loop.py` | 观察-思考-行动主循环，`MAX_STEPS=8` |
| `registry.py` | ToolSpec 注册表，自动编译 OpenAI function schema |
| `llm_adapter.py` | DeepSeek/LangChain 调用抽象（流式 + 同步） |
| `schemas.py` | AgentStep / Trajectory / ToolCall 数据类 |
| `tools/` | 10 个原子工具 handler |

**10 注册工具**：`search_events / get_event_detail / compare_events / compare_platforms / analyze_event_sentiment / search_articles / semantic_search_articles / list_hot_platforms / get_morning_brief / rank_events_by_sentiment`

**评测**（20 query 离线集，详见 [评测指标文档](./评测指标文档.md)）：

| 指标 | 结果 |
|:---|:---|
| 完成率 | 100% (20/20) |
| 工具召回率 | 95% |
| 平均步数 | 3.5（P95=6） |
| 平均延迟 | 26 s（P95=42 s） |
| 引用真实性 | 人工抽查全部可溯源 |

> 详见 → [Agent 算法文档](./Agent算法文档.md)。

### 5.2 LLM 研判（`app/llm.py`）

DeepSeek（OpenAI 兼容）SSE 流式：文章深度分析、事件宏观研判、每日早报、ABSA 方面抽取统一走该链路。

### 5.3 关键词提取（`app/keyword_extraction.py`）

jieba 双路：TF-IDF (`extract_tags`, topK=40) + TextRank (`textrank`, topK=40)，合并去重后取 Top-30 作为词云数据；事件级 `_extract_display_keywords` 引入第三语料源（`ai_summary` 优先 / `content[:500]` 兜底）。

## 八、关键设计决策

### 8.1 为什么不用 LangGraph / AutoGen
自研 ~270 行 Agent Loop，11 个单测全部离线（FakeLLM 注入），切换 LLM Provider 只改 `llm_adapter.py` 一个文件，推理链路完全可审计。

### 8.2 事件排序为何用 `id DESC` tiebreaker
SQLite 同分行返回顺序不确定，叠加 `limit(9)` 后每次刷新 Top-9 集合在同分事件间漂移，前端"闪一下换卡片"。所有 ORDER BY 末尾统一加 `Event.id.desc()` 后稳定。详见 [核心原理文档](./核心原理文档.md) §4.3。

### 8.3 ABSA 为何不用现成模型
公开中文 ABSA 模型训练于电商/餐饮，新闻舆情迁移效果差。改用 LLM 一次调用同时输出 `(aspect, sentiment, evidence)` 三元组，prompt 内嵌强约束。详见 [ABSA 算法文档](./ABSA算法文档.md)。

### 8.4 推荐为何用"分级整数 + 4 维权重"
浮点加权公式在 `heat_score` rebuild 后 ±ε 抖动会让 sort 漂移；分级整数（`article_count > platform_count > id`）在数据集快照内严格稳定。订阅推荐则把 4 维权重显式暴露到前端 UI，便于评委演示打分透明性。
