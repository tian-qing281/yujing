## 一、「刷新」按钮到底做了什么

订阅页右上角的「刷新」按钮调用的是 `loadAll()`（[yujing-ui/src/components/SubscriptionPanel.vue](yujing-ui/src/components/SubscriptionPanel.vue) L390-410）：

```
loadAll() = Promise.all([
  GET /api/subscriptions   // 读订阅清单
  GET /api/blocklist       // 读屏蔽词清单
  GET /api/profile         // 读画像 (top_sources/top_tags/recent_views)
]) → fetchRecommend(0)     // 重新拉第 1 页推荐
```

**关键结论**：
- 「刷新」**不会重新跑爬虫、不会重建事件、不会重算 centroid**
- 仅是「**重读 4 个 GET 接口**」+ 重置分页到第 1 页
- 真正影响推荐结果变化的是后台 scheduler：抓取（每 2 min）→ P1.1 增量聚类（每 10 min）→ centroid 校准（每 6 h）

所以**用户感知的「数据更新」实际来自后台时间轴**，「刷新」只是把「服务端最新一刻的状态」拉到当前页面。

## 二、画像的「兴趣标签」底层是什么

### 数据来源链路

```
用户在前端打开/停留某文章
   ↓
POST /api/track  body={action: "open"|"dwell"|"view", article_id, dwell_ms}
   ↓
后端 update_profile_event (routes.py L3534+)
   ↓
读 articles 表 → article.source_id / article.extra_info["category"]
   ↓
累加到 UserProfile.data JSON 字段:
   { "source_weights": { "weibo_hot_search": 12.5, ... },
     "tag_weights":    { "财经": 8.0, ... },
     "view_history":   [最近 200 条] }
```

### 权重累加规则（routes.py L3604-3613）

| 行为 | 权重增量 |
|---|---|
| `view`（曝光） | +1.0 |
| `open`（点击进入） | +2.0 |
| `dwell`（停留 N ms） | +clamp(N/5000, 1, 5)，即 5s 起步、25s 封顶 |

### 「兴趣标签」即 `tag_weights` 的 top-12

注意：**当前 tag 来源狭窄**——只读 `Article.extra_info.category` 一个字段（routes.py L3593-3601）。这个字段在很多源上是空的（B 站/微博热搜大多没有 category），所以画像 tag 实际命中率不高。

**这是后续可优化的方向**（见 §四 V2 项）：用 `Article.embedding` 反推 tag、或用 LLM 给浏览历史抽取主题。

### 为什么「画像兴趣」加分系数低（默认 3）

因为 `category` 信号弱、噪声大；订阅 keyword 是用户**显式声明**的强信号，所以系数 5。

## 三、推荐的完整打分 + 匹配机制（v1.5 现状）

入口：`GET /api/recommendations`（routes.py L3702）

### Step 1：候选池（Candidates）

```python
cutoff = utcnow() - timedelta(days=7)
candidates = (
    db.query(Event)
      .filter(Event.latest_article_time >= cutoff)
      .order_by(Event.heat_score.desc())
      .limit(200)              # ← 硬上限 200
      .all()
)
```

- **范围**：最近 7 天有更新的事件
- **取法**：按 `heat_score` 倒序前 200
- **意图**：避免全表扫；冷门老事件即便订阅词命中也不会进推荐

### Step 2：黑名单一票否决

```python
if any(t and t in title for t in block_terms):
    continue   # 直接跳过该事件，不参与打分
```

### Step 3：六维加权打分（每事件初始 0）

| 维度 | 公式 | 默认权重 | 触发条件 |
|---|---|---|---|
| ① 订阅 keyword 命中 | `+w_keyword × sub.weight` | 5.0 | `kw in event.title` 字面子串 |
| ② 订阅 event 命中 | `+w_keyword × sub.weight` | 5.0 | 同上 |
| ③ 订阅 source 命中 | `+w_source × sub.weight` | 3.0 | `event.primary_source_id == 订阅源` |
| ④ 画像 source 偏好 | `+w_profile_source × (sw[id]/max_sw)` | 0~3.0 | 比例化，最爱看的源加满分 |
| ⑤ 画像 tag 偏好 | `+w_profile_tag × (Σtag_w/max_tw)` | 0~3.0 | event.keywords 与 tag_weights 交集 |
| ⑥ **S1 语义召回**（新） | `+w_semantic × cos × sub.weight` | 6.0 × cos | cos≥0.45 且订阅词不在标题字面 |

### Step 4：排序

```python
scored.sort(key=lambda x: (-x[0], -(x[1].heat_score or 0)))
# 先按打分降序，相同分按 heat_score 兜底
```

### Step 5：Fallback 兜底

如果 6 维打分后**无任何事件 score>0**（如新订阅、空画像）：
```python
if total_hit == 0 and fallback:
    # 按 heat_score 返回 TOP，并标 _fallback=True
```
前端可识别 `_fallback` 字段提示「暂无个性化命中，按热度推荐」。

### S1 防重保护

字面匹配与语义匹配若都命中同一个订阅词，不重复加分：
```python
if not (sem_kw in event.title):
    score += w_semantic * sem_cos * sem_w
```

## 五、技术决策备忘

- **S1 语义阈值 0.45 的依据**：[scripts/eval_s1_threshold.py](scripts/eval_s1_threshold.py) 实测 BGE-small-zh 短订阅词与长事件标题 mean-pool 后的余弦中心带在 0.30-0.40，0.45 是噪声/真信号拐点
- **S1 权重 6.0 的依据**：cos=0.50 时加 3.0；字面命中 5×weight=5.0；语义不超过字面，不喧宾夺主
- **P1 增量阈值 0.69 的依据**：与全量 FAISS 链路 L2≈0.69 对齐，保证两条路径产出可比
- **centroid 校准必要性**：在线均值 `(c·n + v)/(n+1)` 长期会有浮点累积误差，每 6h 用原始向量重算修正
