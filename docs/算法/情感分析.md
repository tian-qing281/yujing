# 情感分析

> 最后更新 2026-05-18 · 对齐代码版本 · 主入口 [app/services/sentiment_analysis.py](../../app/services/sentiment_analysis.py)

## 1. 任务定义

对每篇文章的 `title + summary` 做**8 分类**情感识别，输出主标签 + 置信度。

| 标签 | 含义 | 应用场景 |
|------|------|---------|
| `neutral` | 中性 / 客观报道 | 默认兜底 |
| `concern` | 担忧 / 焦虑 | 政策、健康、社会议题 |
| `joy` | 喜悦 / 振奋 | 体育胜利、利好新闻 |
| `anger` | 愤怒 / 抨击 | 维权、抨击不公 |
| `sadness` | 悲伤 / 悼念 | 灾难、人物离世 |
| `doubt` | 质疑 / 不信任 | 反转新闻、阴谋论 |
| `surprise` | 惊讶 / 出乎意料 | 突发事件、爆冷 |
| `disgust` | 厌恶 / 反感 | 丑闻、不当言论 |

## 2. 双模型架构

```
            ┌──────────────────────────┐
            │ analyze_sentiment(text)  │
            └────────────┬─────────────┘
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
        [BERT 路径]             [规则路径]
   Johnson8187 Chinese-Emotion   关键词词典 8 类
   - GPU 优先 / CPU 兜底         - 立即可用
   - 首次加载耗时较高             - 无外部依赖
   - 8 分类完整覆盖               - 仅用于降级
              │                     │
              └──────────┬──────────┘
                         ▼
            {label, score, source}
```

### 2.1 BERT 路径

- 模型：`Johnson8187/Chinese-Emotion`（HuggingFace，BERT-base）
- 加载：[app/services/sentiment_model.py](../../app/services/sentiment_model.py) 单例
- 推理：`pipeline("text-classification", truncation=True, max_length=512)`
- 设备：`torch.cuda.is_available() ? "cuda" : "cpu"`
- 输出：原 7 类 + 我们在 [emotion_taxonomy.py](../../app/services/emotion_taxonomy.py) 中映射到 8 类（增加 `concern` 子标签靠规则补足）

### 2.2 规则路径

- 词典在 [sentiment_rules.py](../../app/services/sentiment_rules.py)
- 每标签 30-80 个种子词 + 词性过滤
- 命中加权：直接命中 +3，同义词 +1
- 取最高得分标签；并列时优先 `negative` 类（concern / anger / sadness / disgust）

### 2.3 触发策略

```python
def analyze_sentiment(text: str) -> dict:
    if BERT_AVAILABLE:
        try:
            return _bert_infer(text)
        except Exception:
            pass
    return _rule_infer(text)
```

BERT 失败立刻降级规则，不抛错——保证爬虫主流程不被模型拖垮。

## 3. 接入点

| 调用方 | 时机 |
|--------|------|
| 爬虫入库 [crawler/processing.py](../../app/crawler/processing.py) | 每条文章入库时立即标 `ai_sentiment` |
| 文章深度分析 `POST /api/articles/{id}/analyze` | 用户点详情时按 LLM 全文重新分析 |
| 事件聚合 [routes.py 事件详情](../../app/api/routes.py) | 取所有 article.ai_sentiment 做分布统计 |

## 4. 性能与缓存

| 场景 | 时延 | 说明 |
|------|------|------|
| BERT GPU | ≈ 50 ms / 篇 | A6000 / 4090 |
| BERT CPU | ≈ 200 ms / 篇 | i7 |
| 规则 | < 10 ms | 词典哈希 |
| 缓存 | 0 ms | `article.ai_sentiment` 字段持久化，不重复算 |

> 我们**不做内存缓存**：BERT 是单例 + 字段持久化已足够，重复分析靠 article_id 短路。

## 5. 事件 / 主题情感聚合

文件 [emotion_aggregation.py](../../app/services/emotion_aggregation.py)。

- 对一个 Event 的所有 article.ai_sentiment 求 8 维分布
- 归一化为占比，写入 `Event.sentiment_distribution`（JSON）
- 用 `concern + anger + sadness + disgust + doubt` 五项之和 ≥ 0.5 → 标记 `is_negative=True`
- 提供时序桶：6h / 12h / 24h（API `GET /api/events/{id}/sentiment`）

## 6. 评测

线下抽样 300 条人工标注：

| 指标 | BERT | 规则 |
|------|------|------|
| Macro F1 | 0.71 | 0.42 |
| Neutral 召回 | 0.88 | 0.65 |
| Negative 类平均 P | 0.74 | 0.55 |

BERT 优势在情感跨标签（如 surprise 与 joy 区分），规则适合关键词鲜明类（如 anger 「抗议」「谴责」）。

## 7. 已知限制

1. **反讽 / 黑色幽默**：BERT 也容易判错（如「赢麻了」标 joy 实际 sadness）
2. **8 类细粒度低于真实需求**：用户有「期待」「无奈」诉求，但增类会拉低 F1
3. **跨语言不支持**：英文/混合直接 fallback 规则 → 准确率显著下降

<details>
<summary><b>面试问答</b></summary>

**Q1：为什么用 Johnson8187/Chinese-Emotion 而不是 BERT-base 自训？**
A：（1）我们没有 10k+ 中文情感标注预算；（2）该模型在 NLPCC2014 / SMP2020 等公开集上 F1 ≈ 0.72，与自训上限接近；（3）HuggingFace 直接拉，工程零成本。

**Q2：为什么是 8 分类不是 3 分类（正/中/负）？**
A：3 分类太粗，无法支撑「事件按情感排序」「按 concern 程度推荐」等业务功能。8 分类对齐 Ekman 6 + 中性 + concern（中文社交场景特有「担忧」），是产品迭代后的最终方案。

**Q3：BERT 加载首次很慢怎么解决？**
A：单例 + 主进程启动时预热（[main.py](../../app/main.py) 启动 hook 触发一次 dummy 推理）。冷启 ≈ 8 s，预热后稳定 50ms。

**Q4：规则词典靠人工维护成本高吗？**
A：是。所以我们只在「BERT 不可用」场景用，词典作为安全网。后期会做半自动扩词：用 BERT 高置信样本反向挖词。

**Q5：跨平台情感分布是否会平均掉？**
A：会，所以我们暴露平台维度过滤：`GET /api/events/{id}/sentiment?platform=weibo`。算法层并不平均，仍按文章独立打标后聚合占比。

**Q6：怎么处理一句话两种情感？**
A：BERT 用 softmax top1 + score，我们存的是单标签 + 置信度。如果 top1 score < 0.4 视为不确定，标 `neutral`。多标签场景属于增强项（multilabel head），未实现。
