## 2. 聚类评测

### 2.1 全量聚类

**数据集**：随机抽取 200 对文章，人工标注「应/不应聚为同一事件」（50% 正例）

**评测脚本**：`scripts/eval_clustering.py`（伪代码）
```python
for (art_a, art_b, label) in dataset:
    same_cluster = (event_id(art_a) == event_id(art_b))
    metric.update(label, same_cluster)
```

**指标定义**：
- Precision = 系统判同簇 ∩ 人工同簇 / 系统判同簇
- Recall = 系统判同簇 ∩ 人工同簇 / 人工同簇

**当前结果**（阈值 0.62）：

| 阈值 | P | R | F1 |
|------|---|---|-----|
| 0.55 | 0.81 | 0.89 | 0.85 |
| 0.60 | 0.87 | 0.85 | 0.86 |
| **0.62** | **0.91** | **0.82** | **0.86** |
| 0.65 | 0.94 | 0.76 | 0.84 |
| 0.70 | 0.97 | 0.65 | 0.78 |

→ 选 0.62 是 F1 最高 + P 大于 0.9 的甜点。

### 2.2 增量聚类

**数据集**：取近 24h 100 篇文章，先 hide 它们的事件归属，再用增量聚类挂回，对比是否落到原事件。

| 阈值 | 准确率 | 错挂率（挂到了不相关的事件） |
|------|--------|---------|
| 0.65 | 0.93 | 0.12 |
| **0.69** | **0.88** | **0.06** |
| 0.72 | 0.81 | 0.03 |

→ 选 0.69 是「准确率仍可接受 + 错挂率显著降低」的平衡。

## 3. 情感评测

### 3.1 数据集

300 篇人工标注文章，8 类分布：
- neutral 35%
- concern 18%
- anger 12%
- joy 11%
- sadness 9%
- doubt 7%
- surprise 5%
- disgust 3%

### 3.2 BERT 路径

| 类别 | P | R | F1 |
|------|---|---|-----|
| neutral | 0.79 | 0.88 | 0.83 |
| concern | 0.65 | 0.62 | 0.63 |
| anger | 0.81 | 0.72 | 0.76 |
| joy | 0.74 | 0.79 | 0.76 |
| sadness | 0.71 | 0.65 | 0.68 |
| doubt | 0.55 | 0.48 | 0.51 |
| surprise | 0.62 | 0.55 | 0.58 |
| disgust | 0.69 | 0.51 | 0.59 |
| **Macro** | **0.70** | **0.65** | **0.71** |

### 3.3 规则路径

| 指标 | 数值 | 备注 |
|------|------|------|
| Macro F1 | 0.42 | 显著低于 BERT |
| anger F1 | 0.61 | 关键词鲜明类表现好 |
| surprise F1 | 0.22 | 表达多样性高，词典覆盖差 |

**结论**：BERT 是主路径，规则只作降级。

## 4. ABSA 评测

### 4.1 方法

50 篇人工标注 ground-truth 方面集合（每篇 3-6 个方面）。

**方面匹配**：用 BGE 算系统方面与 GT 方面的余弦相似度，≥ 0.7 视为命中。

### 4.2 结果

| 指标 | 数值 |
|------|------|
| 方面 Precision | 0.74 |
| 方面 Recall | 0.62 |
| 方面 F1 | 0.68 |
| 方面 sentiment 一致率 | 0.71 |

### 4.3 误差分析

- **召回低主因**：LLM 倾向输出「热点 / 主要方面」，长尾方面易漏
- **sentiment 不一致**：方面情感比文章主情感更细致，存在「方面 positive 但人工标 neutral」的细粒度分歧

## 5. 推荐评测

### 5.1 方法（离线重放）

- 用户浏览历史 → 隐藏最近 5 条
- 用前 N-5 条产生推荐 → 看隐藏的 5 条在推荐 TopK 中的命中率
- 由于单用户，数据规模有限（≈ 50 条历史），结果有方差

### 5.2 指标

| 指标 | 含义 | 数值 |
|------|------|------|
| Hit@10 | 隐藏 5 条至少 1 条在 Top10 | 0.41 |
| NDCG@10 | 折损累积增益 | 0.63 |
| MAP@10 | 平均精度 | 0.32 |

### 5.3 消融

| 配置 | NDCG@10 |
|------|---------|
| 仅订阅匹配 | 0.51 |
| 仅画像推断 | 0.49 |
| 仅语义相似 | 0.58 |
| **全融合** | **0.63** |

→ 语义相似贡献最大，融合 +0.05。

## 6. Agent 评测

### 6.1 方法

100 轮人工对话，每轮记录：
- 用户 query
- 最终回答
- 工具调用链
- 人工评分（1-5 分）：相关性 / 准确性 / 表达流畅度

### 6.2 指标

| 指标 | 数值 |
|------|------|
| 平均评分（1-5）| 3.9 |
| 答非所问率 | 8% |
| 幻觉率（编造事件 / 数字）| 3% |
| 平均工具调用步数 | 3.2 |
| 平均端到端延迟 | 4.8 s |

### 6.3 错误分类

- 40% 答非所问 → query 模糊（如「最近怎么样」）
- 30% 工具选错 → LLM 选了 `search_articles` 而非 `search_events`
- 20% 数据缺失但 LLM 没明说「无数据」（应改 prompt）
- 10% LLM 返回格式异常

## 7. 搜索评测

### 7.1 方法

100 个真实 query（如「小米 SU7」「淄博烧烤」），人工标注每个 query 的 Top10 应包含的事件。

| 指标 | Meili | SQL ILIKE |
|------|-------|-----------|
| MRR@10 | 0.79 | 0.61 |
| Recall@10 | 0.85 | 0.68 |
| 平均延迟 | 35 ms | 120 ms |

→ Meili 是主路径，ILIKE 仅作 Meili 故障降级。

## 10. 已知缺陷

1. **数据集规模小**：所有评测样本 < 500，方差较大
2. **无在线 A/B**：推荐 / Agent 缺少真实用户行为反馈
3. **类别不平衡**：情感 disgust 类样本仅 9 个，F1 不稳
4. **跨平台口径**：不同平台「热度」单位不统一，对比指标只能定性
