## 1. 一句话定位

「**舆镜 YuJing**」= 8 平台热搜采集 → 多维 AI 分析（聚类 + 情感 + 方面） → 自然语言 Agent 问答 + 个性化订阅推荐 的一站式舆情系统。

## 3. 数据生命周期

```
爬虫拉到 → Article 入库 → 情感 BERT 即时打标 → 写 ArticleEmbedding（BGE 向量）
   ↓
全量聚类 / 增量聚类 → Event（+centroid + heat_score）
   ↓
事件归并到主题 → Topic
   ↓
个性化召回（订阅 + 画像）→ /api/recommendations
   ↓
Agent 工具调用 → 自然语言回答
```

## 4. 核心算法栈

| 层 | 技术 | 选型理由 |
|----|------|---------|
| 向量化 | BGE-small-zh-v1.5（512 维）| 中文 STS 效果优；小到能 CPU 跑 |
| 聚类 | Union-Find + 复合相似度（cos+time+platform）| 支持全量 + 增量两条路径，可解释 |
| 增量聚类 | Centroid 平均 + 阈值挂载 | 100 篇/30min 量级下 50ms |
| 情感 | BERT (Chinese-Emotion) 8 类 + 规则兜底 | 双轨容错，离线可降级 |
| 方面分析 | LLM (DeepSeek) JSON 抽取 + 文件缓存 | 新闻方面开放集，监督方案行不通 |
| 全文检索 | MeiliSearch + SQLite ILIKE 兜底 | Meili 故障不阻塞 |
| 语义检索 | FAISS IVF（NLIST=64）| 万级文章 ms 级召回 |
| Agent | OpenAI tool_call 协议 + 自写 8 步 loop | 不依赖 LangChain，调试简单 |
| LLM | DeepSeek-chat（默认）/ OpenAI 可切 | 国内便宜 + 中文好 |
| 调度 | APScheduler AsyncIO | FastAPI 单进程内调度，无外部 broker |

## 5. 关键并发与容错

| 资源 | 上限 | 策略 |
|------|------|------|
| 深度分析（ABSA + 全文 LLM）| `Semaphore(3)` | 排队，防止 LLM token 雪崩 |
| BGE 向量化 | batch=16 | CPU/GPU 自适应 |
| 爬虫请求 | ThreadPool max=10 | 各源 interval 错峰 |
| Agent 单轮 | MAX_STEPS=8 | 防死循环 |
| MeiliSearch | 失败 fallback ILIKE | 不阻塞前端 |
| BERT 情感 | 失败 fallback 规则 | 不阻塞入库 |
| LLM 调用 | 重试 2 次 + 30s 超时 | 失败可降级返回模板 |

## 6. 关键阈值速查

| 参数 | 默认 | 含义 |
|------|------|------|
| `SEMANTIC_CLUSTER_THRESHOLD` | 0.62 | 全量聚类相似阈值 |
| `INCR_CLUSTER_THRESHOLD` | 0.69 | 增量聚类相似阈值 |
| `SEMANTIC_TIME_HALF_LIFE_HOURS` | 12 | 时间衰减半衰期 |
| `EMBED_DIM` | 512 | BGE 向量维度 |
| `PROFILE_TTL_SECONDS` | 1800 | 用户画像推断缓存 |
| `NEIGHBOR_MIN_COS` | 0.55 | 推荐相似下限 |
| `MAX_STEPS` (agent) | 8 | Agent 工具调用上限 |
| `BRIEF_HOUR` / `BRIEF_MINUTE` | 8 / 0 | 早报触发时刻 |
