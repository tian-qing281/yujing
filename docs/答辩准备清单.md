## 二、高频问答

| 问题 | 30 秒标准回答 |
|------|---------------|
| 数据来源是否合法？ | 仅采集公开热榜接口，遵守 robots，本地存储不二次分发；无登录类抓取。 |
| 聚类阈值如何确定？ | 双层 Otsu 在每批数据上自适应分桶，无需人工调参；论文方法迁移到舆情场景。 |
| 为什么用 BGE-small 而不是 large？ | small 512 维 + 后续可 INT8，单条编码 8ms，对于聚类已足够；large 26ms 性价比低。 |
| Agent 会不会幻觉？ | 强制 tool-calling，所有事实数据来自工具返回；trace 全程留痕可审计，无工具调用即拒答。 |
| 与清博 / 知微的差异？ | 我们做「开源 + 本地化 + Agent 智能体」，他们是闭源 SaaS；本系统可一键部署在本机或私有化环境。 |
| 平台改版怎么办？ | crawler 抽象 `BaseSource`，单平台失效不影响整体；凭据失效已有 UI 友好提示。 |
| 「100% 任务完成率」如何度量？ | 50 道任务集，要求模型给出非空且事实正确的回答；详见评测文档。 |
| 冷启动慢怎么办？ | 模型懒加载 + 启动跳过重抓；首屏 <1s。 |
| 为什么 24h / 7d 数据相同？ | 这是 `fetch_time` 字段语义所致（首次入库时间）；不是数据缺失。后续可加 `last_seen_time` 字段区分入库时间与上榜时间。 |
| Cookie 维护成本如何？ | 仅知乎 / 微博需要 Cookie；提供「凭据资产配置」UI 一键更新，每次失效约 5 分钟操作。 |
| ABSA 与传统情感的区别？ | 传统情感是「整篇 → 1 个标签」；ABSA 是「整篇 → N 个 (方面, 情感, 证据句)」。例：同一则新闻里「警察+」/「胇事者-」可同时输出，LLM 一次调用 + 文件缓存 < 5ms 多次命中。 |
| 推荐打分的 4 维权重含义？ | 订阅词命中 / 订阅源命中 / 画像·常看源 / 画像·兴趣词命中。只要一个权重上去，该侧贡献就上涨；UI 现场滑动即可重新打分，本地持久化。 |
| 为什么事件排序里严重依赖 `id DESC`？ | SQLite 同分行返回顺序不确定，叠加 `limit(9)` 后 Top-9 集合会「闪一下」；尾部加 id DESC 作稳定 tiebreaker 后多次刷新顺序严格一致。 |
