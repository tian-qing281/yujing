# 订阅推荐

> 最后更新 2026-05-18 · 主入口 [app/services/recommend_service.py](../../app/services/recommend_service.py) · 画像 [app/services/profile_inference.py](../../app/services/profile_inference.py)

## 1. 业务目标

让用户在「我的订阅」/「为你推荐」页面看到与其**显式订阅 + 隐式行为**最相关的事件，不被无关热搜淹没。

## 2. 三维融合打分模型

```
final_score(event, user) =
    keyword_match     * 5.0    ← 标题 / 摘要含订阅关键词
  + source_weight     * 3.0    ← 订阅了该源（如 weibo / b站）
  + profile_source    * 3.0    ← 画像推断的偏好源
  + profile_tag       * 3.0    ← 画像推断的兴趣标签
  + semantic_sim      * 4.0    ← 订阅向量 vs 事件 centroid 余弦
  - blocked_penalty   * 999    ← 命中屏蔽词直接踢出
  + heat_score        * 0.5    ← 热度兜底
```

排序后 TopN 返回。若融合分均为 0（冷启 / 无订阅 + 无画像），按 `heat_score` 兜底返回。

## 3. 订阅数据结构

[模型定义](../../app/database.py) `Subscription` 表：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 主键 |
| `kind` | str | 类型：`keyword` / `source` / `semantic` |
| `value` | str | 关键词文本 / 源 id / 语义短句 |
| `weight` | float | 权重（用户可调）|
| `embedding` | BLOB | 仅 kind=semantic 时存，BGE 512 维 |
| `created_at` | datetime | |

支持的 kind：

| kind | 触发逻辑 | 示例 |
|------|---------|------|
| `keyword` | 标题/摘要 ILIKE 命中 | "小米 SU7" |
| `source` | 文章 source_id 匹配 | "weibo_hot_search" |
| `semantic` | 订阅向量 vs 事件 centroid cos ≥ 0.55 | "国产新能源车出海" |

## 4. 用户画像（隐式）

### 4.1 行为追踪

前端每次用户进入事件详情：

```js
fetch('/api/profile/track', {body: {article_id, action: 'view'}})
```

后端写入 `UserProfile.view_history`（JSON 数组，最大 50 条）。

### 4.2 画像推断

文件 [profile_inference.py](../../app/services/profile_inference.py)。

**触发时机**：
- 任何 `/api/profile` 或 `/api/recommendations` 调用，若 `inferred_at` 距今 > 1800s 触发后台重算
- 用户点「重置画像」立刻清空

**推断流程**：

```
1. 取 view_history TopK=50
2. 从每篇文章取 jieba TextRank Top12 关键词 → 累计权重
3. 取相似事件（NEIGHBOR_TOPK=80，NEIGHBOR_MIN_COS=0.55）
4. 过滤用户已看过的
5. 聚合相似事件的关键词 → 加入候选 tag
6. 过滤 blacklist（用户删过的 tag）
7. 写 inferred_tags + source_weights + tag_weights
8. 30min TTL
```

### 4.3 用户可干预

| 操作 | API | 持久化字段 |
|------|-----|---------|
| 删除自动标签 | `DELETE /api/profile/tag?tag=xxx` | `inferred_tags_blacklist` |
| 添加手动标签 | `POST /api/profile/tag` | `manual_tags` |
| 删除某偏好源 | `DELETE /api/profile/source/{id}` | 从 `source_weights` 移除 |
| 重置整体画像 | `POST /api/profile/reset` | 清空 view_history / weights / tags |

## 5. 召回与排序

```
        ┌─────────────────────────┐
        │ 候选池：近 7 天所有事件 │   (Event.updated_at >= now - 7d)
        └────────────┬────────────┘
                     │
        ┌────────────▼────────────┐
        │ 过滤：blocklist 命中踢出 │
        └────────────┬────────────┘
                     │
        ┌────────────▼────────────┐
        │ 打分：融合 5 项 + 热度  │
        └────────────┬────────────┘
                     │
        ┌────────────▼────────────┐
        │ 排序 TopN (默认 N=30)   │
        └─────────────────────────┘
```

## 6. 冷启策略

| 场景 | 行为 |
|------|------|
| 0 订阅 + 0 浏览历史 | 按 `heat_score` 返回 Top30 |
| 0 订阅 + 有浏览历史 | 走画像推断 → tag/source 加权 |
| 有订阅 + 0 浏览历史 | 走订阅打分 |
| 都有 | 融合，且语义订阅最优先 |

## 7. 性能

| 阶段 | 数据规模 | 耗时 |
|------|---------|------|
| 候选池查询 | ≈ 1500 events | 30 ms |
| 打分 | 1500 × 5 项 | 80 ms |
| 排序 + 序列化 | TopN=30 | 20 ms |
| 画像推断（背景）| 50 历史 + 80 邻近 | 200 ms |

合计 P95 ≈ 450 ms。

## 8. 复盘与教训

### 8.1 已经踩过的坑

1. **画像 TTL 一开始没设**：每次请求都重算 → P95 飚到 2s。改 30min TTL 后立刻降。
2. **关键词权重 5.0 vs 语义 4.0**：早期语义权重最高，但用户反馈「订阅 SU7 却看到无关电车文章」。调低语义提高关键词后好转。
3. **「画像数据为空」误导**：UI 只看 `top_sources.length`，但实际 `tag_weights` 累积了 191 次浏览 → 加重置按钮 + UI 明确分区。
4. **冷启全 0 用户看到一片空白**：补 heat_score 兜底，并标 `_fallback=True` 前端 UI 显示「未匹配，按热度兜底」。
5. **订阅 embedding 一开始用 jieba 关键词组合算 + 一直跑**：性能差。改为存订阅向量到 `Subscription.embedding` 字段（创建时一次性算）。

### 8.2 仍待改进

- 没有 negative feedback：用户「不感兴趣」按钮还没接入打分模型
- 仅一种排序方式：未支持「最新 / 最热 / 最相关」切换（前端已有按钮，后端排序硬编码）
- 画像可解释性弱：用户看到 tag 但不知道为什么有这个 tag（应展示「来自哪 3 篇文章」）

<summary><b>面试问答</b></summary>

**Q1：为什么是这 5 项不是更多？**
A：项数越多权重调参越难。我们从 7-8 项收敛到 5 项，把弱信号合并（如 platform_match 合到 source_weight 里）。

**Q2：权重 5/3/3/3/4 怎么定？**
A：经验起步 + 小样本调优：keyword 必须最高（显式信号），semantic 次之（弱显式），三项 profile 等权（隐式信号）。无在线 A/B，靠 NDCG@10 离线评估。

**Q3：为什么画像 TTL 30min？**
A：用户行为不会秒级变化，30min 兼顾「新行为快速反映」和「性能」。低于 5min CPU 跑不过来，高于 1h 用户感知不到反馈。

**Q4：怎么解决用户兴趣漂移？**
A：view_history 用 FIFO 50 条窗口，旧行为自动衰减。手动重置按钮兜底彻底重启。

**Q5：怎么防止订阅推荐陷入信息茧房？**
A：（1）保留 heat_score 项作为多样性引入；（2）冷启 fallback 按热度；（3）即将做：每 N 条推荐插 1 条「探索性」内容（如跨平台热度高但与画像无关）。

**Q6：语义订阅怎么算向量？**
A：用户输入「国产新能源车出海」→ 调 BGE 编码 → 写 `Subscription.embedding`（512-d）→ 与事件 centroid 算余弦相似度。

**Q7：blocklist 怎么实现？**
A：用户填关键词 → 写 `Blocklist` 表。打分前先扫文章 title + summary，命中任一词直接 -999 分（等同剔除）。
