# 模块 · 数据模型与表结构

> 最后更新 2026-05-18 · 主入口 [app/database.py](../../app/database.py)

## 1. 存储栈

| 介质 | 用途 |
|------|------|
| **SQLite (WAL)** | 主数据：Article / Event / Topic / Subscription / UserProfile / Blocklist |
| **SQLite FTS5** | 文章全文虚拟表 `articles_fts` |
| **MeiliSearch** | 事件 / 主题搜索索引（可选）|
| **FAISS** | 向量索引（in-process，每次启动从 BLOB 重建）|
| **文件缓存** | ABSA / 早报 / 报告导出物 |

## 2. ER 总览

```
Source(8 个) ──< Article >── EventArticle ──> Event ──< TopicEvent ──> Topic
                   │
                   │ 1:1
                   ▼
           ArticleEmbedding (BGE 512-d BLOB)

User(default) ──┬── Subscription (kind / value / weight / embedding)
                ├── Blocklist (term)
                └── UserProfile (view_history / weights / inferred_tags)
```

## 3. 核心表

### 3.1 `articles`

| 字段 | 类型 | 索引 | 说明 |
|------|------|------|------|
| `id` | int pk | auto | |
| `source_id` | str | idx | 源 id（如 `weibo_hot_search`）|
| `item_id` | str | unique(source_id, item_id) | 源内主键 |
| `title` | str | | |
| `summary` | text | | |
| `url` | str | | |
| `published_at` | dt | idx | 源给的时间 |
| `crawled_at` | dt | idx | 入库时间 |
| `heat_score` | float | idx | 平台热度 |
| `rank` | int | | 平台榜内排名 |
| `extra` | JSON | | 源特定字段 |
| `content` | text | | 全文（Jina Reader 抓取）|
| `ai_summary` | text | | LLM 摘要 |
| `ai_sentiment` | str | idx | 8 类标签 |
| `ai_sentiment_score` | float | | |
| `aspects` | JSON | | ABSA 结果数组 |

唯一约束：`(source_id, item_id)` 防止同一源重复入库。

### 3.2 `events`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int pk | |
| `title` | str | 取簇内 heat_score 最高的 article.title |
| `summary` | text | LLM 一句话总结（可空）|
| `centroid` | BLOB | 512-d float32 |
| `keywords` | JSON | jieba TextRank Top12 |
| `heat_score` | float | 所有文章 heat 加权 |
| `article_count` | int | |
| `first_seen_at` | dt | |
| `updated_at` | dt | 最近一篇文章入簇时间 |
| `sentiment_distribution` | JSON | `{neutral: 0.32, concern: 0.21, ...}` |
| `is_negative` | bool | concern+anger+sadness+disgust+doubt ≥ 0.5 |
| `top_platforms` | JSON | 平台分布 |

### 3.3 `event_articles`（关联表）

| 字段 | 说明 |
|------|------|
| `event_id` | fk events |
| `article_id` | fk articles |
| `similarity` | 入簇时的相似度 |

唯一约束：`(event_id, article_id)`。

### 3.4 `topics`（事件归并主题）

| 字段 | 说明 |
|------|------|
| `id` | pk |
| `title` | 主题标题 |
| `keywords` | JSON |
| `event_count` | 包含事件数 |
| `heat_score` | 聚合热度 |
| `created_at` / `updated_at` | |

### 3.5 `topic_events`（关联表）

`(topic_id, event_id)` 唯一。

### 3.6 `article_embeddings`

| 字段 | 说明 |
|------|------|
| `article_id` | pk + fk |
| `embedding` | BLOB（512 × float32 = 2KB）|
| `created_at` | |

> 单独抽表是为了让 articles 表保持轻量，且重建索引时方便批量读 BLOB。

### 3.7 `subscriptions`

详见 [订阅推荐.md](订阅推荐.md)。

### 3.8 `blocklist`

| 字段 | 说明 |
|------|------|
| `id` | pk |
| `term` | 屏蔽词 |
| `created_at` | |

### 3.9 `user_profiles`

详见 [用户画像与推断.md](用户画像与推断.md)。

### 3.10 `articles_fts`（FTS5 虚拟表）

```sql
CREATE VIRTUAL TABLE articles_fts USING fts5(
    title, summary, content,
    content='articles', content_rowid='id',
    tokenize='unicode61'
);
```

通过触发器与 `articles` 同步，提供 SQL 全文搜（MeiliSearch 降级路径）。

## 4. 迁移

[migrations/](../../app/migrations/) 或 `database.py` 启动钩子里增量加字段：

```python
def ensure_columns(engine):
    # 启动时检查 articles 表是否有新字段，没有就 ALTER TABLE ADD COLUMN
    ...
```

避免引入 Alembic 复杂度（单机 + 字段变动少）。

## 5. 索引清单

| 表 | 索引 | 用途 |
|----|------|------|
| articles | `(source_id, item_id)` unique | 去重 |
| articles | `crawled_at` | 时间查询 |
| articles | `ai_sentiment` | 按情感过滤 |
| articles | `heat_score desc` | 热度排序 |
| events | `updated_at desc` | 近期事件 |
| events | `heat_score desc` | 热度排序 |
| event_articles | `(event_id, article_id)` unique | |
| event_articles | `event_id` | 事件 → 文章 |
| event_articles | `article_id` | 文章 → 事件 |

## 6. 容量参考

连续运行 7 天（单机）：

| 表 | 行数 | 大小 |
|----|------|------|
| articles | ~ 50,000 | ~ 200 MB（含 content）|
| events | ~ 6,000 | ~ 10 MB |
| topics | ~ 1,500 | ~ 2 MB |
| event_articles | ~ 50,000 | ~ 3 MB |
| article_embeddings | ~ 50,000 | ~ 100 MB（2KB × 5w）|
| articles_fts | ~ 50,000 | ~ 50 MB |
| **总计** | - | **~ 500 MB** |

## 7. 备份

```bash
# 在线热备
sqlite3 runtime/db/yujing.db ".backup runtime/backups/yujing_$(date +%F).db"
```

WAL 模式下 `.backup` 命令安全，不阻塞写入。
