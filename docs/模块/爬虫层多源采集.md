# 模块 · 爬虫层（8 源多平台采集）

> 最后更新 2026-05-18 · 主入口 [app/crawler/](../../app/crawler/) · 调度 [app/scheduler.py](../../app/scheduler.py)

## 1. 设计目标

- 8 个独立平台并发抓取，**单源故障不阻塞其他源**
- **错峰调度**避免突刺
- **Cookie 缺失自动降级**返回空（不报错）
- 入库即时打标（情感 + 向量化），让下游分析免轮询

## 4. 入库流程

[processing.py](../../app/crawler/processing.py)：

```
for item in items:
    article = Article(...)
    db.merge(article)        # 按 (source_id, item_id) 去重
    if 新增:
        # 1. 情感 BERT 即时打标（< 200ms）
        article.ai_sentiment = analyze_sentiment(title + summary)
        # 2. BGE 向量化写 ArticleEmbedding 表
        emb = embed(title + summary)
        ArticleEmbedding(article_id=article.id, embedding=emb).save()
db.commit()
```

**为什么入库时同步打标 + 向量化？**
- 情感 BERT < 200ms 可承受
- 向量化用进程内 LRU 缓存命中率高
- 让下游聚类 / 推荐 / 搜索免轮询

## 5. 同步入口

| 入口 | 触发 | 行为 |
|------|------|------|
| `GET /api/sync` | 用户 / 调度 | 触发全 8 源并发抓取 |
| `GET /api/sync/status` | 用户轮询 | 返回当前 phase / errors |
| APScheduler | 每 5 min | `_run_sync_job()` 自动 |

并发：`asyncio.gather(*tasks)`，每源用 `httpx.AsyncClient(timeout=10s)`。

## 6. 失败处理

| 失败类型 | 行为 |
|---------|------|
| 网络超时 | 该源返回空 + 记 `sync_status.errors[source_id]` |
| HTTP 4xx / 5xx | 同上 |
| Cookie 失效（如 403）| 该源返回空，前端 UI 提示「Cookie 失效」 |
| 单 item 解析失败 | 跳过该 item，其他正常入库 |
| DB 写入失败 | 回滚该批次，不影响其他源 |

**核心原则**：永远返回 `(success_count, error)`，绝不抛异常给主流程。

## 8. 正文抓取

`POST /api/articles/{id}/analyze` 触发：

1. 拿 article.url
2. 调 Jina Reader API（免费，无 key，`https://r.jina.ai/{url}`）
3. 返回 markdown 正文
4. 写 `article.content`
5. 触发 LLM 摘要 + ABSA

并发：`_analyze_global_semaphore = asyncio.Semaphore(3)`，防止 LLM 雪崩。

## 10. 反爬应对

- **错峰**：8 源 interval 不一致，避免同时打源方
- **UA 池**：默认 5 个常见浏览器 UA 轮询
- **Cookie 池**：单 Cookie 即可，可选多 Cookie 轮询（未启用）
- **代理池**：生产部署可在 httpx Client 注入 `proxies=`
- **被封降级**：返回空 + 标 source 不可用，等下次周期重试

    interval_seconds = 180
    default_item_limit = 20

    async def fetch(self, limit):

## 12. 已知限制

1. **8 源不能水平扩展**：单机调度上限
2. **Cookie 手动管理**：失效需用户手动更新
3. **无重试退避**：超时直接放弃当次，等下一周期
4. **抓取速率限制依赖错峰**：未做严格 QPS 控制
