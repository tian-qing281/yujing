# 模块 · 语义索引与全文搜索

> 最后更新 2026-05-18 · 主入口 [app/services/semantic_index.py](../../app/services/semantic_index.py) / [app/services/meili_service.py](../../app/services/meili_service.py)

## 1. 双检索栈

| 引擎 | 用途 | 故障降级 |
|------|------|---------|
| **MeiliSearch** | 全文检索（事件 / 文章）| SQLite ILIKE |
| **FAISS** | 语义相似 / KNN 召回 | 无降级（必备）|

两者**互补**：全文擅长精确匹配（"小米 SU7"），语义擅长意图召回（"国产新能源车出海"）。

## 2. FAISS 语义索引

### 2.1 索引结构

| 项 | 值 |
|----|---|
| 向量维度 | 512（BGE）|
| 距离 | 内积（L2 归一后 = 余弦）|
| 索引类型 | < 5000 用 `IndexFlatIP`；超过用 `IndexIVFFlat` |
| NLIST | 64 |
| NPROBE | 8 |
| TOPK | 20 |

### 2.2 构建

```python
def rebuild_index(lookback_hours=72):
    # 1. 从 ArticleEmbedding 表加载 BLOB
    vectors, ids = load_embeddings(lookback_hours)
    # 2. 训练（IVF 必须 train）
    if len(vectors) >= NLIST * 39:
        index = faiss.IndexIVFFlat(quantizer, dim, NLIST)
        index.train(vectors)
    else:
        index = faiss.IndexFlatIP(dim)
    # 3. add
    index.add(vectors)
    # 4. 持久化到全局变量（无 .index 文件）
    _GLOBAL_INDEX = index
    _GLOBAL_IDS = ids
```

启动时自动重建一次（≈ 1s / 1w 条）。

### 2.3 触发场景

| 调用方 | 用法 |
|--------|------|
| 全量聚类 | 构临时 FAISS 召回近邻对，做 Union-Find |
| 增量聚类 | 候选事件 centroid 索引召回 |
| `GET /api/semantic/neighbors` | 用户查文章相似 |
| 推荐 | 订阅向量召回事件 |
| Agent 工具 `semantic_search_articles` | LLM 调用 |

### 2.4 维护

| 任务 | 频率 |
|------|------|
| 重建全局索引 | 启动时 + `POST /admin/semantic/index` |
| Event centroid 校准 | 每 2 h |
| 增量加新向量 | 文章入库时同步 add 到索引 |

## 3. MeiliSearch 全文索引

### 3.1 索引

| 索引名 | 内容 |
|--------|------|
| `events` | event_id / title / summary / keywords / heat_score / updated_at |
| `articles` | article_id / title / summary / source_id / published_at |
| `topics` | topic_id / title / keywords |

主键 `*_id`，按 `heat_score / updated_at` 排序。

### 3.2 启动

[main.py](../../app/main.py) 启动 hook：

```python
if MEILI_ENABLED:
    # Windows: 自动 spawn meilisearch.exe
    # Linux: 期望系统已装
    _meili_proc = subprocess.Popen([MEILI_BINARY, ...])
    wait_until_ready(host=MEILI_HOST, timeout=10)
    sync_index()  # 把 SQLite 数据塞进 Meili
```

### 3.3 同步策略

- 事件 / 文章 创建/更新时**异步** push 到 Meili（不阻塞主流程）
- 失败入队列下次重试
- 定时全量重同步（手动 admin 触发，非必需）

### 3.4 搜索 API

```python
client.index("events").search(
    q="小米 SU7",
    {
        "limit": 20,
        "sort": ["heat_score:desc"],
        "filter": "updated_at > 1700000000",
    }
)
```

### 3.5 故障降级

```python
def search_events(q):
    try:
        return meili_search(q)
    except Exception:
        return sqlite_ilike_fallback(q)  # 慢但能用
```

SQLite ILIKE：
```sql
SELECT * FROM events
WHERE title LIKE '%' || ? || '%' OR summary LIKE '%' || ? || '%'
ORDER BY heat_score DESC LIMIT 20;
```

性能差 3-4 倍，但保证可用性。

## 4. SQLite FTS5（备用）

`articles_fts` 虚拟表（[模块/数据模型与表结构.md](数据模型与表结构.md)），提供本地全文搜（Meili 不可用时）。

```sql
SELECT a.* FROM articles a
JOIN articles_fts f ON a.id = f.rowid
WHERE articles_fts MATCH ?
LIMIT 20;
```

## 5. 性能

| 操作 | 规模 | 时延 |
|------|------|------|
| Meili 搜索 | 6000 events | 30-50 ms |
| SQLite ILIKE | 同上 | 100-200 ms |
| FAISS 近邻 TopK=20 | 50k vectors | 5-15 ms |
| FAISS IVF 训练 | 5w 向量 | ≈ 1s |
| FAISS 全量重建 | 5w 向量 | ≈ 1s |

## 6. API 接入

| 接口 | 后端 |
|------|------|
| `POST /api/events/search` | Meili → ILIKE 兜底 |
| `POST /api/articles/search` | Meili → FTS5 兜底 |
| `GET /api/semantic/neighbors` | FAISS |
| `GET /api/semantic/index-status` | 返回 FAISS 状态 |
| `POST /admin/semantic/index` | 触发重建 |

## 7. 已知限制

1. **FAISS in-process**：多 worker 部署需要每个 worker 各自一份索引（内存 N 倍）
2. **Meili 二进制单机**：未做集群
3. **同步索引非事务**：SQLite 写成功但 Meili 推送失败可能短时间不一致
