# 舆境（yujing）升级路线图

> 版本：2026-05-09 · 计算机设计大赛备战阶段
> 编写原则：每项升级给出现状 / 改造点 / 验收标准 / 工作量 / 依赖 / 风险，避免空泛。
> 工作量记号：XS≤2h，S≤1d，M≤3d，L≤1w，XL≥1w。

---

## 一、功能升级

### F1. 事件时间轴可视化（高 ROI）
- **现状**：事件详情仅展示标题/摘要/相关文章列表，时间维度信息被埋没。
- **改造点**：在 `EventModal` 内嵌入 ECharts 横向时间轴；节点按 `fetch_time` 与各源 `extra_info.time` 排序；hover 弹出文章浮动卡片，点击直达原文。
- **验收**：单事件 ≥3 篇相关文章时显示时间轴；轴上节点点击可跳转源页面；移动端折叠为竖向时间线。
- **工作量**：S（约 0.5 天）
- **依赖**：现有 `EventModal.vue`、`marshal_event.articles` 字段
- **风险**：低

### F2. 智能预警订阅（推送）
- **现状**：`/api/ai/alerts` 仅前端轮询展示，刷新页面即丢失，无外部触达能力。
- **改造点**：
  1. 新增 `Subscription` 表（`id, owner, keyword, source_id, threshold_heat, channel, target, enabled`）
  2. `_refresh_events_cache` 末尾比对历史事件快照，命中订阅时入队 `outgoing_alerts`
  3. 后台 worker 将告警通过 SMTP / 飞书 Webhook / 企业微信 Webhook 推送
- **验收**：用户配置「新疆 + 微博 + 热度>50万」，命中后 30 秒内收到 Webhook 通知；可在 UI 中查看推送历史。
- **工作量**：M（约 2 天）
- **依赖**：SMTP 凭据 / 飞书机器人 URL；可复用现有 `event_hub_refresh_lock`
- **风险**：中（需要轻量的去重 / 退避策略避免风暴）

### F3. Agent 多轮记忆 + 会话历史
- **现状**：`/api/agent/chat` 每次单轮，无历史上下文，连续提问需要重述背景。
- **改造点**：
  1. 客户端生成 `conversation_id` 持久化在 `localStorage`
  2. 后端建 `Conversation` / `Message` 表保存最近 N 轮的 `user/assistant/tool` 消息
  3. 进入 Agent loop 前注入「最近 4 轮摘要 + 用户最新问题」
- **验收**：连续提问「5 月舆情 → 把它做成早报」能自动接续，无需重述。
- **工作量**：M（约 1.5 天）
- **风险**：低

### F4. 报表导出 Word/PPT
- **现状**：仅支持 PDF 导出。
- **改造点**：用 `python-docx` + `python-pptx` 复刻 PDF 模板（封面 / 目录 / 事件分页 / 附录）；前端 ExportButton 加入格式下拉。
- **验收**：导出的 Word 可直接二次编辑；PPT 每事件一页，自带情绪卡片与词云图片。
- **工作量**：M（约 2 天）
- **风险**：低

### F5. 跨平台比较仪表盘扩展
- **现状**：`CompareDashboard` 仅支持双平台对比。
- **改造点**：升级为 N 平台雷达图（5 维：情绪倾向 / 平均热度 / 事件时延 / 主题多样性 / 跨平台重合度）。
- **工作量**：S（约 1 天）
- **风险**：低

## 二、性能升级

### P1. 增量聚类（高 ROI）
- **现状**：`rebuild_events` 每次全量重建 9000 篇文章约 20 秒；定时刷新都全跑，浪费 CPU 且阻塞 `event_hub_refresh_lock`。
- **改造点**：
  1. `Article` 表新增 `last_clustered_at`
  2. 增量任务只拉新增/更新文章，向 FAISS 做 KNN 查询；命中既有事件则挂载，否则单独成簇
  3. 每 6 小时跑一次全量整合，避免事件碎片化
- **验收**：单分钟新增 30 篇时聚类耗时 <500ms；24 小时累积漂移 <2% 簇心偏移
- **工作量**：M（约 2 天）
- **风险**：中（碎片化）

### P2. FAISS IVF → HNSW
- **现状**：`IVF-Flat nlist=15` 对 252 文档过拟合，FAISS 自身警告「训练点不足」。
- **改造点**：切换 HNSW32（无需训练，向量动态插入）；保留 IVF 作为大数据量后端可切换。
- **验收**：召回率 ≥ IVF 的 95%；QPS ≥ IVF 的 1.5 倍
- **工作量**：S（约 0.5 天）
- **风险**：低（FAISS 接口一致）

### P3. SSE / Agent 工具调用并行化
- **现状**：Agent loop 串行调用工具，10 工具长链最长 26 秒。
- **改造点**：检测同一批 `tool_calls` 之间是否有依赖（参数引用上一步结果即视为有依赖），无依赖则 `asyncio.gather` 并发执行；trace 时间线照旧。
- **验收**：典型「双工具调用」场景从 6s → 3s；trace 顺序仍可读
- **工作量**：S（约 1 天）
- **风险**：低

### P4. 嵌入批量化 + 模型 INT8 量化
- **现状**：BGE-small-zh 单条 forward。
- **改造点**：批量 32；启用 `torch.quantization.quantize_dynamic`；CPU 推理时启用 oneDNN。
- **验收**：批量 100 文档编码耗时 <1.5s；与 FP32 余弦相似度差异 <1%
- **工作量**：M（约 2 天）
- **风险**：中

### P5. SQLite WAL checkpoint 调度
- **现状**：长跑后 `*.wal` 文件可达 100MB+，启动慢。
- **改造点**：每 30 分钟后台执行 `PRAGMA wal_checkpoint(TRUNCATE)`。
- **工作量**：XS（约 1 小时）
- **风险**：低

## 三、UI 升级

### U1. 暗色主题（高 ROI）
- **现状**：仅 light，DaisyUI 自带 dark 主题但未启用。
- **改造点**：`AppHeader` 新增切换按钮，`localStorage` 持久；ECharts 双套配色（dark 用 `dark` registerTheme）。
- **工作量**：S（约 1 天）
- **风险**：低

### U2. 全局命令面板（Cmd+K）
- **现状**：跨平台搜索需进入「全景事件聚合」页。
- **改造点**：自研 Modal 或引入 `vue-command-palette`；索引内容包括所有平台 / 最近事件 / Agent 预设 / 设置项。
- **工作量**：M（约 1.5 天）
- **风险**：低

### U3. 移动端 PWA
- **现状**：移动端可看，无法安装、无离线。
- **改造点**：`vite-plugin-pwa` + manifest + Service Worker 缓存事件列表。
- **验收**：手机「添加到桌面」后离线可看缓存事件
- **工作量**：M
- **风险**：低

### U4. 骨架屏统一
- **现状**：列表/详情加载时卡片闪烁。
- **改造点**：全局 `<SkeletonCard>` 组件替换所有 spinner。
- **工作量**：S
- **风险**：低

### U5. 工作区视图保存
- **现状**：当前筛选条件刷新即丢失。
- **改造点**：保存命名预设（时间窗 + 平台 + 排序），可一键加载。
- **工作量**：S
- **风险**：低

## 四、自由扩展（可观测性 / 工程化）

### X1. Prometheus + Grafana
- **现状**：`/api/sync/status` 已有原始数据，缺统一指标暴露。
- **改造点**：`prometheus_client` 暴露 `/metrics`，指标含抓取耗时、事件数、Agent 工具命中率、LLM token 用量、SSE 连接数。
- **工作量**：S（半天）
- **ROI**：长期监控价值高

### X2. Sentry 错误上报
- **改造点**：后端 `sentry-sdk[fastapi]`，前端 `@sentry/vue`，免费版每月 5k 事件足够。
- **工作量**：XS（2 小时）

### X3. A/B 测试框架
- **当前判断**：答辩项目阶段可暂缓，留作后续商用化储备。
